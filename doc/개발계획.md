# MinsPDFViewer 개발 계획 및 기능 현황

## 1. 프로젝트 개요
`MinsPDFViewer`는 WPF 기반의 경량·고성능 PDF 뷰어 및 편집기입니다.
PDFium(최신 Google 엔진, 자체 P/Invoke 래퍼)을 통한 렌더링·텍스트·주석 처리, BouncyCastle 기반 디지털 서명(RFC 3161 타임스탬프, LTV, 그래픽 도장 서명), Windows Media OCR을 결합하여 문서를 평탄화(Flattening)하지 않고 원본 구조를 유지하며 주석(Annotation) 및 Searchable PDF를 생성·관리하는 것을 목표로 합니다.

### 1.1 특장점
- **인쇄 제한 문서도 인쇄**: PDF 권한의 '인쇄 금지'(소유자 암호로 건 제한)를 무시하고 인쇄한다. 인쇄 창에 `인쇄 제한 해제` 표시
- **화면 그대로 인쇄**: 저장하지 않은 주석·페이지 순서·회전·삭제·빈 페이지를 반영해 인쇄 (원본 파일은 건드리지 않음)
- **초경량 검색 가능한 PDF**: 글리프 없는 632바이트 폰트로 OCR 텍스트 층을 덧붙여 파일 크기가 거의 늘지 않음 (MobileScan과 같은 규약)
- **원본 구조 유지 편집**: 평탄화 없이 주석·서명을 증분 저장

### 1.2 폴더 구조 (2026-10-23 정리)
```
MinsPDFViewer.sln, README.md
src/MinsPDFViewer/   앱 (Views·Models·Services·Pdf·Common·Assets), 네임스페이스는 모두 MinsPDFViewer
tests/               MinsPDFViewer.Tests (xUnit), TestFiles (테스트 PDF, 대용량은 git 제외)
doc/                 개발 문서
assets/              디자인 원본 (로고·아이콘)
build/               publish.bat · makeSetup.bat · release.bat · installer.nsi
                     + 빌드 산출물 Debug\<프로젝트>\ · Release\<프로젝트>\ · publish\ · obj\ (git 제외)
lib/                 NuGet에 없는 외부 DLL 자리 (현재 비어 있음, *.dll 무시 규칙 예외)
dist/                설치 파일 출력 (git 제외)
```
- `Views/` 창·대화상자, `Models/` 뷰모델·저장 모델, `Services/` 앱 서비스(로드·렌더·저장 조율, 검색, OCR, 인쇄, 기록, 인증서), `Pdf/` PDF 구조를 직접 다루는 코드(PDFium 편집 저장, OCR 텍스트 층, 북마크, 서명·검증, `PdfSyntax`), `Common/` 변환기·로그
- 테스트 파일 경로는 솔루션 루트(`MinsPDFViewer.sln`)를 위로 찾아 `tests/TestFiles` (`PdfServiceTests.FindTestFilesDirectory`)
- 출력 경로: 루트 `Directory.Build.props`가 모든 프로젝트의 `OutputPath`(`build\<구성>\<프로젝트>\`, TFM·RID 하위 폴더 없음)와 `BaseIntermediateOutputPath`(`build\obj\<프로젝트>\`)를 정함. `src\`·`tests\`에는 소스만. 실행 파일 `build\Debug\MinsPDFViewer\MinsPDFViewer.exe`
- 배포: `build\release.bat` → `build\publish`(게시) → `dist\MinsPDFViewer_Setup_v<버전>.exe`

## 2. 지금까지 반영되어 있는 기능 목록 (완료 현황)

### 2.1 PDF 뷰어 코어
- [x] **PDFium 렌더링 엔진**: 고속 PDF 페이지 렌더링, 페이지 가변 줌/스크롤, 연속 스크롤 뷰 (2026-10-23부터 보이는 영역 기준 스케줄러, 4장)
- [x] **선명한 텍스트 렌더링 (ClearType/LCD Text)**:
  - 모니터 DPI와 줌에 맞춘 1:1 장치 픽셀 렌더링, 앱 회전은 PDFium이 그림 자체를 돌려 그림 (화면에서 다시 늘이거나 돌리지 않음)
  - PDFium `FPDF_ANNOT | FPDF_LCD_TEXT` (RGB 서브픽셀 텍스트 안티앨리어싱)
  - WPF `<Image>`는 `Stretch="Fill"`(비트맵 = 칸 크기), `SnapsToDevicePixels`·`UseLayoutRounding`, 그림자는 페이지와 분리된 형제 요소
- [x] **썸네일 사이드바**: 좌측 페이지별 썸네일 표시 및 페이지 이동 네비게이션
- [x] **북마크(목차) 트리**: 계층형 북마크 로드 및 페이지 점프, 추가/삭제/이름수정/들여쓰기(Indent/Outdent)
- [x] **단일/선택 페이지 회전**: 좌측 썸네일에서 선택한 페이지 또는 현재 활성 페이지만 단독 회전(90도/270도 및 누적 회전각 저장 지원)
- [x] **페이지 조작**: 페이지 순서 변경(Drag & Drop), 페이지 삭제, 빈 페이지 삽입

### 2.2 암호화 PDF 지원
- [x] **비밀번호 보호 PDF 열기**: 암호화된 PDF 파일 감지 시 비밀번호 입력 다이얼로그(`PasswordDialog`) 표시
- [x] **비밀번호 재시도 및 취소 처리**: 비밀번호 불일치 시 안내 및 재입력 유도, 유효한 암호로 문서 및 텍스트 레이어 로드

### 2.3 주석(Annotation) 기능

- [x] **텍스트 상자(FreeText)**: 캔버스 기반 텍스트 상자 생성, 이동, 크기 조절, 글꼴/색상/크기 변경
- [x] **비평탄화(Non-flattened) 저장**: PDF 표준 사양 준수(Appearance Stream, /DA, /DR 리소스 딕셔너리 관리)
- [x] **PDFium/Foxit 호환성**: 외부 뷰어(Foxit, Adobe, Chrome 등)에서도 주석이 정상 표시되도록 호환성 패치 적용

### 2.4 전자서명 및 검증
- [x] **BouncyCastle 기반 서명**: PFX/P12 인증서 및 Windows 인증서 저장소 연동
- [x] **시각적 도장(Visual Stamp)**: 서명 위치 마우스 드래그 지정, 서명 이미지 스탬프 합성
- [x] **증분 저장(Incremental Update)**: 기존 서명 파기를 방지하는 ByteRange 기반 증분 서명
- [x] **서명 검증**: 무결성 검증, 인증서 체인 유효성 및 만료 여부 확인

### 2.5 OCR 및 Searchable PDF 엔진 (pdf-parser 초경량 방식)
- [x] **Windows Media OCR**: 한국어/영어 언어 팩 지원, 이미지 기반 PDF의 텍스트 및 Bounding Box 인식
- [x] **초경량 Glyphless Text Layer (`PdfGlyphlessOcrService`)**:
  - `build_glyphless_ttf`: 532바이트의 극소형 TrueType 빈 글리프 폰트 바이너리
  - `/Type0` + `/Identity-H` + `/CIDFontType2` + `/CIDToGIDMap` + `/ToUnicode` Identity CMap 구조 생성
  - Recursive XY-Cut 알고리즘(`RecursiveXyCut`): 2단 문서, 문단, 제목 간격을 인식하여 자연스러운 읽기 순서 정렬
  - `BT 3 Tr ... Tz ... <hex> Tj ET`: 투명 텍스트 렌더링, 단어 간 공백(" ") 첨부 및 가로 배율(`Tz`) 조정을 통해 단어 간격 및 검색 호환성 확보
  - 기존 수백 MB ~ 1GB 이상 파일 크기 폭증 문제 완전 해결 (수십 KB 수준 유지)
  - **좌표계 (2026-10-23)**: `OcrWordInfo.BoundingBox`는 줌과 무관한 PDF 포인트, PDFium이 원본 페이지를 그린 화면(앱 내 회전 전) 기준 왼쪽 위 원점. 저장 시 CropBox 오프셋·원본 `/Rotate`(저장본 `/Rotate` − 앱 회전)로 사용자 공간에 변환하고, 회전 페이지는 `Tm` 축을 돌려 화면에서 가로로 읽히게 넣음
  - **MobileScan과 같은 글꼴 규약**: Ascent 880 / Descent -120, 기준선 = 단어 아래 + 0.12em → 뷰어 선택 상자 = 단어 상자. ToUnicode `beginbfrange`는 블록당 100개 이하(100·100·56)
  - **글리프**: 632바이트 TTF(fontTools 생성), GID 1은 넓이 0인 대각선 윤곽(칠할 것 없음). 완전히 빈 글리프는 PDFium이 세로 방향(90°/270° 페이지) 글자를 텍스트로 인식하지 못함
  - **증분 기록 견고화**: 원본 내용을 `q … Q`로 감쌈(공유 q 스트림), `/Resources` 상속·간접 참조·중첩 사전·간접 `/Font` 처리(`PdfSyntax`), `/Contents`가 배열 객체를 가리켜도 처리, trailer에 `/Info` 유지, 다시 OCR하면 이전 층(`/MinsOcrLayer` 표식) 교체, 암호화 PDF는 건너뜀(로그)

### 2.6 검색(Search) 기능
- [x] **순차적 페이지 탐색**: 기존 루프 인덱스 누적 버그(0, 2, 5, 9... 삼각수 페이지 건너뛰기) 수정하여 모든 페이지를 누락 없이 1페이지씩 탐색
- [x] **문서 끝/시작 래핑(Wrap-around) 탐색**: 처음/끝 도달 시 재탐색 결과 정상 반영 및 해당 페이지 스크롤 이동
- [x] **메모리 내 OCR 단어 실시간 검색**: OCR 실행 직후 아직 파일로 저장하지 않은 상태에서도 `pageVM.OcrWords`를 통해 즉시 단어 및 다중 어절 검색/하이라이트 지원
- [x] **다중 일치 항목 시각화**: 페이지 내 모든 매치 항목을 노란색 하이라이트로 표시하고, 현재 선택된 포커스 단어는 주황색으로 강조 표시

### 2.7 텍스트 선명도 강화 및 로딩 성능 최적화

- [x] **초기 문서 로딩 및 이전 열람 위치 복원 최적화**:
  - `_historyService`의 이전 페이지 위치(`initialPageIndex`) 복원 시 해당 가시 영역 페이지 렌더링에 최고 우선순위 부여
  - 썸네일 백그라운드 렌더링 시 메인 뷰 렌더링 작업(`PdfService.HasPendingRenders` = 스케줄러 작업 중)에 양보 및 `initialPageIndex` 중심 외향 순차 생성. 썸네일은 고해상도 그림이 오기 전 페이지 자리 표시로도 쓰임
  - `InitializeDocumentAsync`에서 `PdfiumLock` 획득 횟수를 페이지별 N회에서 1회로 축소하여 다중 페이지 로딩 지연 단축

### 2.8 인쇄 (2026-10-23)
- [x] **진입**: 툴바 `🖨 인쇄`, `Ctrl+P` (텍스트 상자 편집 중에도 — 편집 내용을 확정한 뒤 인쇄)
- [x] **현재 상태 인쇄** (`PrintService.PrepareAsync`):
  - 원본과 화면이 같으면 원본 파일을 별도 PDFium 문서로 스트림으로 열어 인쇄 (1GB급도 메모리에 올리거나 다시 저장하지 않음)
  - 다르면 저장 경로(`SavePdf(forPrinting: true)`)로 임시 PDF를 만들어 메모리에 열고(`PdfiumDocument.OpenBytes`) 임시 파일은 즉시 삭제. OCR 텍스트 층·북마크 재작성은 생략, 보안은 벗겨 저장(`FPDF_REMOVE_SECURITY`)
  - 변경 판단(`HasPendingChanges`): 페이지 수·순서(`OriginalPageIndex`)·빈 페이지·회전, 저장형 주석(텍스트·형광펜·밑줄·이미지)의 서명을 파일에서 읽은 서명(`PdfPageViewModel.LoadedAnnotationSignature`)과 비교. 좌표는 페이지 크기 비율이라 줌과 무관. 검색 하이라이트·OCR 단어·북마크는 인쇄와 무관해 제외
- [x] **인쇄 제한 무시**: `FPDF_GetDocPermissions`(열린 문서 `PdfiumDocument.Permissions`)로 원본의 인쇄 금지(bit 3)를 감지해 표시만 하고, 인쇄는 PDFium으로 직접 그려 권한을 보지 않음
- [x] **인쇄 창** (`Views/PrintWindow`): 프린터·드라이버 `속성`(DocumentProperties, DEVMODE 반영)·용지·매수·한 부씩, 페이지(전체/현재/지정 `1-3, 5, 8-`, `5-3` 역순), 크기(맞춤/큰 페이지만 축소/실제 크기), 방향(자동=페이지마다/세로/가로), 주석 포함, 흑백
- [x] **미리보기**: 실제 인쇄와 같은 배치 계산(`PrintLayout.Compute`)·같은 렌더 플래그(`FPDF_PRINTING`, 주석, 흑백)로 용지 위 페이지를 표시, ‹ › / PageUp·PageDown으로 넘김, 보이는 크기만큼만 렌더
- [x] **출력**: `System.Drawing.Printing.PrintDocument` + PDFium이 프린터 DC에 직접 렌더(`FPDF_RenderPage(HDC)`, 벡터 그대로, 비트맵 스풀 아님). 페이지마다 `PdfiumLock`, 페이지별 용지 방향(`QueryPageSettings`, 가로로 정의된 용지 보정), 화면용 감마·샤픈 미적용. 백그라운드 스레드에서 인쇄, 상태바 진행 표시

## 4. 렌더링 엔진 재설계 (2026-10-23, P1 완료)

### 4.1 배경 (검토 결과)
- 화면이 뭉개진 직접 원인: 2단계 렌더에서 고해상도 패스가 새 요청에 밀려 버려지면 그 페이지는 다시 요청되지 않음 → 반 해상도로 남음 (검색·책갈피 이동처럼 스크롤이 연달아 일어날 때). 캡처 분석으로 실제 정보량이 화면 해상도의 절반 이하임을 확인
- 페이지 템플릿의 `DropShadowEffect`가 페이지 그림을 감싸는 `Border`에 걸려 있어 WPF가 중간 표면에 다시 그림 (흐림 요인)
- 라이브러리 중복: PdfiumViewer(2018년 PDFium, WinForms 래퍼, 2019년 이후 유지보수 중단) + 같은 pdfium.dll 직접 호출(3곳) + 정규식 PDF 파서 4개
- 페이지를 그릴 때마다 페이지를 다시 열고 600 dpi 스캔 이미지를 다시 풂, 주석 읽기는 페이지마다 문서 전체를, 검색은 페이지마다 파일을 다시 엶. 모든 작업이 잠금 하나에 줄 섬. 렌더는 중간 취소 불가
- 서명·북마크 증분 기록기가 교차 참조 스트림(PDF 1.5+, Acrobat 등 대부분의 최신 PDF)을 읽지 못함 (`tests/TestFiles/normal.pdf`로 확인) → P2

### 4.2 엔진: 최신 PDFium (bblanchon.PDFium.Win32)
- Google PDFium(크롬 PDF 엔진)을 매주 자동 빌드해 배포하는 NuGet 패키지. Apache-2.0, 의존성 없음, 2017년부터 매주 월요일 빌드, 누적 다운로드 1천만 이상. PyPDFium2·libvips·pdfium-render 등이 사용
- PdfiumViewer와 다른 점: PdfiumViewer는 **관리 코드 래퍼**가 멈춰서 엔진도 2018년에 고정됐다. bblanchon은 **엔진 바이너리만** 제공하고, 래퍼(P/Invoke)는 우리 코드다. 엔진 개발은 Google이 계속한다
- 남는 위험과 대응
  - 1인 관리 패키지 → 버전을 고정(`158.0.8111`)하고 검증한 뒤에만 올린다. 패키지가 사라져도 `lib/`에 pdfium.dll을 직접 두면 되고(`!lib/**/*.dll` 예외 준비됨), 공개된 빌드 스크립트로 직접 빌드도 가능
  - PDFium C API는 안정적이지만 "Experimental" 표시 함수는 바뀔 수 있음 → 래퍼(`Pdf/Native/PdfiumNative.cs`) 한 곳에만 선언, 올릴 때 헤더와 대조
  - `FPDF_FILEACCESS.m_FileLen`이 Windows에서 32비트(unsigned long) → 4GB 넘는 파일은 미지원 (현재 최대 1GB). 여는 순간 안내
  - 이 패키지는 XFA·V8(자바스크립트) 없는 빌드 → 순수 XFA 양식(드묾)은 "기다려 주세요" 안내 페이지만 보임. 일반 AcroForm·주석·서명은 영향 없음
- **버전 올릴 때 점검표**
  1. `bblanchon.PDFium.Win32` 버전을 바꾸고 패키지의 `build/native/include/pdfium/*.h`와 `PdfiumNative.cs`·`PdfiumEditService.NativeMethods` 선언을 대조 (특히 `unsigned long`=uint, `FPDF_BOOL`=int, 구조체 버전 필드)
  2. `dotnet test` (특히 `PdfiumEngineTests`, `PdfServiceTests`, `PrintServiceTests`)
  3. 수동: 큰 스캔 PDF 스크롤·줌 500%·책갈피 이동, 회전 페이지 검색 하이라이트, 암호 PDF(한글 암호), 인쇄 미리보기·실제 인쇄, 서명 검증
  4. 개발 문서에 버전·결과 기록

### 4.3 설계 (P1)
- **하나의 엔진**: PdfiumViewer 제거. `PdfiumNative`(P/Invoke 한 곳) + `PdfiumDocument`(문서 하나 = 핸들 하나)
  - 파일은 스트림으로 연다(`FPDF_LoadCustomDocument`) → 1GB 파일도 통째로 메모리에 올리지 않음, 한글 경로 문제 없음
  - 최근 페이지(`FPDF_PAGE`·텍스트 페이지)를 열어 둔 채 재사용 → 디코딩된 이미지도 재사용. 주석·검색·텍스트 추출·북마크·권한이 모두 같은 핸들을 씀
- **렌더 스케줄러** (`PageRenderScheduler`, 전용 스레드)
  - 화면이 보이는 영역을 알려 주면(스크롤·줌·창 크기·탭 전환·책갈피 이동) 보이는 페이지 → 앞뒤 미리 그릴 페이지 순으로 그린다
  - **해상도 보장**: 페이지마다 "지금 그려진 해상도"를 기록하고, 목표와 다르면 될 때까지 다시 그린다 (요청이 버려지는 구조 없음)
  - **즉시 취소**: 점진 렌더(`FPDF_RenderPageBitmap_Start` + 일시정지 콜백)로 그리는 중에도 보이는 영역이 바뀌면 멈춤
  - **고배율**: 페이지 전체 그림은 최대 픽셀 수로 제한하고, 보이는 부분만 원래 해상도의 상세 타일로 겹쳐 그림 (메모리 일정, 확대해도 선명)
  - **정확한 픽셀**: 장치 픽셀 크기 그대로 그리고, 앱 회전은 PDFium `rotate`로 그림 자체를 돌린다(레이아웃 회전 제거). 그림자는 별도 요소로 분리
  - 그려 둔 그림은 메모리 한도 안에서 캐시 → 다시 스크롤해 오면 바로 표시. 아직 안 그려진 페이지는 썸네일을 임시로 늘려 보여 줌
- **검색 하이라이트**: `FPDF_PageToDevice`로 PDF 좌표 → 화면 좌표 (원본 `/Rotate`·CropBox·앱 회전 모두 반영)
- 범위 밖 (다음 단계, 5장): P2 증분 기록기 통합(교차 참조 스트림 지원, 서명 검증에 PDFium 서명 API), P3 표준 주석(FreeText `/AP`), P4 100% = 실제 크기, 모니터 DPI 변경 대응

### 4.4 구현 (P1)
- `Pdf/Native/PdfiumNative.cs`: 쓰는 PDFium 함수 선언 전부 + `Pdfium.Lock`(전역 잠금, 모든 호출 직렬화)·`EnsureInitialized`·오류 문구. 경로·암호는 UTF-8(`LPUTF8Str`) — 최신 PDFium 규약, 한글 경로·한글 암호 동작
- `Pdf/PdfiumDocument.cs`: 문서 한 개. `Open`(파일 스트림, 공유 읽기) / `OpenBytes`(메모리 고정), 페이지 LRU 12개, `RenderToBuffer`(타일·회전·점진 렌더·취소), `RenderToDC`(인쇄), `PageToView`/`ViewToPage`(1/16 픽셀 정밀도), `FindText`, `GetBoundedText`, `ReadAnnotations`, `GetBookmarks`, `Permissions`, `SignatureCount`
- `Services/PageRenderScheduler.cs`: 전용 스레드 하나. 작업 순서 = 보이는 페이지 전체 그림 → 보이는 부분 상세 타일 → 앞뒤 페이지 → 보이는 페이지 주석 읽기. 전체 그림 최대 1,200만 픽셀, 상세 타일은 보이는 영역 + 96px 여유를 256px 격자에 맞춤. 캐시 384MB(LRU). 페이지별 `RenderedBaseKey`(픽셀 크기·회전)로 "필요한 해상도가 그려졌는지" 판단
- `Views/MainWindow`: `UpdateRenderViewport` — 실제로 배치된 페이지 컨테이너(`VirtualizingStackPanel.Children`)의 `PageGrid` 위치를 스크롤 뷰와 겹쳐 보이는 영역 계산, 스크롤·줌·탭 전환·창 크기·DPI 변경 때 레이아웃 뒤 한 번만(`RequestViewportUpdate`). 책갈피·썸네일 이동은 레이아웃 전이라도 목적 페이지를 먼저 그리도록 힌트
- 페이지 템플릿: 썸네일(자리 표시) → 전체 그림 → 상세 타일(Canvas) → 선택·주석 층. `LayoutTransform` 없음
- 검색(`FindTextRectsInView`)·영역 텍스트(`ExtractTextInRect`)·이미지 복사(선택 영역만 3배 해상도 타일)·OCR 입력 이미지·인쇄·미리보기가 모두 열린 `PdfiumDocument` 사용. OCR 단어(원본 화면 좌표) 검색 결과도 앱 회전·줌 반영(`SearchService.OcrRectToView`)
- 썸네일도 앱 회전 반영 (이전에는 회전해도 썸네일은 그대로)

### 4.5 검증
- 같은 PDFium 버전의 Linux 빌드(`bblanchon.PDFium.Linux` 158.0.8111)로 래퍼 코드를 그대로 컴파일해 확인: 타일 = 전체 그림의 잘라낸 부분(픽셀 일치), 점진 렌더 = 일반 렌더, 취소 시 즉시 중단, `rotate=1`은 시계 방향 90°, 화면↔PDF 좌표 왕복, 검색 상자가 실제 글자 위(회전 0°·90°, CropBox 오프셋·원본 `/Rotate` 270° 문서 포함), 한글 경로, UTF-8 암호(한글 암호 포함), 서명 수·주석·북마크 읽기
  - 이 과정에서 찾은 버그: 스트림 열기 콜백이 지역 변수를 캡처한 뒤 그 변수를 비워 페이지를 못 읽음 → 수정
- 테스트 추가 `tests/MinsPDFViewer.Tests/PdfiumEngineTests.cs` (5종): 한글 경로 + 타일 일치 + 점진 렌더, 회전 방향, 취소, 검색 상자 위치(줌 1.5·회전 90°)와 영역 텍스트, OCR 좌표 회전 변환
- WPF 화면 동작(스크롤·줌·책갈피 이동 체감, 고배율 타일 이음매)은 Windows에서 확인 필요
